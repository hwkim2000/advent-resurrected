# Detailing pass: decisions applied while merging (voice-input)

These are the choices made when the 19 refined requirements were merged. They resolve the "decisions needed" the per-requirement QA pass raised. Where the user has not decided, the default below is used and flagged in the Open Questions section as "Default chosen, confirm".

1. Alt+M short tap latches like a pointer tap (R4.7/R4.8 refined). R17 must not say Alt+M is hold-only.
2. Unavailable set by a permission-based `denied` at detection (R2.4) is recoverable by a later permission change to granted/prompt (R2.5). Unavailable set by R7.1, 7.2, 7.7 (runtime errors) is final for the page lifetime. Update the Glossary entry "Unavailable" and R7.8 accordingly. Suspended takes precedence over Ready (R1.11).
3. Cleaning (R8.1) maps U+2018, U+2019, U+02BC to apostrophe and U+2010 to hyphen BEFORE the character filter, so "plover's" survives.
4. The classic-command predicate used by the Voice_Layer is `isClassicCommandText` from `src/shared` (NOT src/parser; fix the Introduction/Glossary text that says src/parser/eligibility.ts). It needs zzword and oldstyle, so the Voice_Layer receives an injected predicate `isClassicCommand(text): boolean` bound to the running game (supplied through the voice port by the controller/main), instead of the Voice_Layer reading engine state.
5. Check order for a final result (R8.12 precedence, mirrored in R9.12): (a) prompt kind/phase undeterminable or phase not `ready`: silent; (b) `filename` prompt: TYPE THE FILE NAME.; (c) empty cleaned text: DIDN'T CATCH THAT.; (d) `yesno` prompt: yes/no mapping, else Meta block, else submit unchanged; (e) `command` prompt: Magic_Match; (f) Meta_Command block; (g) submit. Magic words are NOT recognised at yesno/filename prompts.
6. Meta_Command rule for spoken text (R9.6, replaces the narrower "classic command of one or two words" trigger): for prompt kinds `command` and `yesno`, withhold a spoken line with TYPE THAT COMMAND; DO NOT SAY IT. when ANY of its first two tokens (the words the classic parser would read) satisfies `isMetaWord`. Longer sentences whose first two tokens are not Meta words go through the AI path, where Meta outputs are rejected, so a Meta word later in a sentence cannot reach the engine via the AI; if the AI falls back, the classic parser reads only the first two tokens, which are not Meta by this rule. Flag this default.
7. R10: the 4th PLUGH alias is `plug h`; tokenization joins runs of single-letter tokens and splits on hyphens (R10.18) for the whole matcher; the first Alternative that yields a Magic_Match wins even if Alternative 1 would be a classic command (magic wins). Single-token short aliases (`fi`, `fo`, `fum`, `fee`, `fie`, `foe`, `foo`) match alone by exact alias (as in R10.3); flag `fum` alone as a default. Prefix runs `fee fie` and `fee fie foe` match (R11.2). All lines of a multi-line Magic_Match are submitted even if an earlier one changes the prompt kind.
8. R12: reincarnation is the same game and does NOT reset the Deflection_Count; the count resets on boot, restart offer after game over, a mode change that starts a game, an invalid/cleared autosave. The Deflection happens even where XYZZY would do nothing. Deflection_Line fixed text: `SAY IT ALOUD. HOLD THE MIC OR ALT+M. TYPE XYZZY AGAIN IF YOU MUST.` (66 chars; contains ALOUD, MIC, ALT+M). It reaches assistive technology through the same live output as other Narrator_Lines.
9. R13: gate result carries 1 to 3 narrator lines; Deflection_Count capped at DEFLECTION_LIMIT; game-start notification stays a single callback with fan-out in main.ts; R13.10 and R19.8 both list src/parser as unmodified.
10. R14.1: the capture ban covers microphone-input only (no getUserMedia, MediaRecorder, or audio node fed by the microphone); Web Audio for synthesized sound in other specs is NOT banned. R18.2/R18.10 narrowed to match (no global AudioContext ban). A dismissed permission prompt is treated as `denied` (Chrome reports not-allowed for both).
11. R15: Permissions-Policy line only `microphone=(self)`; no other policy directives added in this spec. `check:dist` enforces R15.1 to R15.5 (R16.6 widened). If the manual check finds the headers block recognition, a follow-up changes them (R15.7).
12. R16/R18.13: the Voice_Disclosure_Text lives in ONE exported constant module under src/shared (design picks the filename) imported by main/DOM glue, tests and scripts/check-dist.ts; index.html carries the static text and a test and check:dist assert equality. README test is a Vitest test (not part of check:dist).
13. R17: the `Listening` live-region announcement at session start is DROPPED (a screen reader speaking while the microphone is open could be captured by the recogniser); listening is conveyed by LISTENING... text and aria-pressed. Announce `Heard: ...` and calm messages after the session. Update R6.7 and R17.7 accordingly. aria-disabled activation stays silent. Mic_Button description is not extended.
14. R5.12 start-confirmation timeout: keep, but note it can also fire if the player takes very long to answer the browser permission prompt; treat as `other` (calm message). Flag for real-device check.
15. R19: new criteria numbering from the refined R19 is accepted; fix cross-references from other requirements.
16. R6.7 and R10.10 must agree: exactly one `Heard: ` announcement per processed final result.
